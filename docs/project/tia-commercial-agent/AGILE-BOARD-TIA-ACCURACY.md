## 1. Goal

Make Test Impact Analysis (TIA) in TestRadius **accurate on every run**: given a PR diff, the selected test set must be the *correct minimal* set — no missed impacted tests, no random/unrelated tests, and no silent fallback when evidence actually exists.

Today TIA is directionally right but has measurable accuracy gaps found while running match tests on `hbahuguna/py-key-value` (297 `def test_*` functions → 1308 collected pytest nodeids) and `hbahuguna/typer`:

- Evidence covers only a **slice** of the suite (instrumentation analyzes the 3 smallest test files), so most tests never get EVIDENCE edges.
- Symbol attribution and changed-symbol resolution are **name/line-overlap based**, producing false positives (e.g. 132 tests selected for a 1-file change) and false negatives.
- The static dependency graph is unscoped (import/call resolution by bare name).
- Selection is silently **capped** (10 symbols) with no truncation signal.
- Evidence can be **stale** relative to the PR head.
- Results are not **verified** — a run can "COMPLETE" with 0 persisted mappings (observed on project 5). *(fixed by **D1**)*

The finish line: a **shadow-validation harness** proves, against a full-suite baseline, that the selected subset never misses a failing test across a corpus of PRs.

## 3. Locked decisions (do not revisit without product owner)

| # | Decision | Answer |
|---|----------|--------|
| A1 | Unit of a "test" | A **collected pytest nodeid** (parametrizations are distinct tests). Used for numerator and denominator consistently. |
| A2 | Instrumentation coverage target | **100% of collected test files** by default; runtime bounded via sharding/parallelism, never silent truncation. |
| A3 | Selection caps | **No silent caps.** Caps may exist for cost only, and MUST emit `truncated: true` + counts; if truncation would drop impacted tests, force fallback. |
| A4 | Evidence freshness | Evidence is valid **only for the commit SHA it was built against**. Drift → stale → rebuild or fall back. |
| A5 | Fail loud | A run whose expected mappings are not verifiably persisted MUST fail (`ERROR`), never `COMPLETED`. |
| A6 | Determinism | Same diff + same evidence → identical selection. All selection queries are stably ordered. |

- **D1 — Done (2026-10-13).** Mapping persistence is now **transactional and verified**, and silent zero-edge completions are impossible. `Neo4jClient.run_in_transaction(statements, verify=None)` runs a list of `(cypher, params)` statements in **one atomic transaction** (commit-all-or-rollback-all); a failing statement or a raising `verify` callback rolls the whole thing back and re-raises. `Neo4jStore._bulk_store_edges` no longer swallows errors: it dedupes edges, writes in a single transaction, **re-counts** the stored `[:EVIDENCE]` edges for the exact `(test, symbol)` keys inside that same transaction, and raises the new `PersistenceError` if the count ≠ the number of distinct mapping edges (or if the write throws) — replacing the old `except: return 0`. Both instrumentation routes now fail loudly on a non-empty mapping set that persists 0 edges: `/projects/{id}/instrumentation/run` raises → the worker's existing handler records `InstrumentationRun(status="ERROR")` (not `COMPLETED`); `/projects/{id}/map-tests` emits an `error` event instead of `COMPLETED` with `mappings: 0`. **Live:** project 3 (py-key-value) run → `status COMPLETED, edges 40295`, exactly matching `MATCH (:TestSymbol {project_id:3})-[e:EVIDENCE]->(:Symbol) RETURN count(e)`; project 5 (typer, the zero-edge case) → `COMPLETED, edges 113557`, coverage 99.0%, DB count 113557 (was 0 edges / silent fallback before).
